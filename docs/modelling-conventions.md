# Modelling conventions (all volumes)

These rules apply to every model in the collection. The generator library `tools/aef_engine.py` implements them.

## 1. Workbook architecture

Sheets appear in this order:

1. **Cover**: version, status, how to use, sheet map, colour code, disclaimer, master check.
2. **Inputs**: scenario selector and global inputs.
3. **Domain input sheets**, e.g. `Products`.
4. **Scenarios**: Base / Downside / Severe levers, plus the *ACTIVE* column used by formulas.
5. **Outputs**: `Dashboard`, `KPIs`, `Annual`, domain outputs such as `Unit_Economics`.
6. **Calculations**: `FS`, domain calculation sheets, `Financing`, `Timeline`.
7. **Checks**.

Information flows in one direction: Inputs → calculations → statements → outputs. No output sheet feeds a calculation.

## 2. Time-based sheets

| Column | Content |
|---|---|
| A | Label |
| B | Unit |
| C | Total, or last value for balances |
| D | Opening balance (blank = 0) |
| E… | Period 1…N |

- Rows 4–6 hold month #, period-end date and year #. They are linked to `Timeline`.
- Panes are frozen at E7.
- The default periodicity is monthly over 60 months. Annual views use `SUMIFS` on the year row for flows and `INDEX(…, year×12)` for balances.

## 3. Formatting

| Element | Convention |
|---|---|
| Hard-coded input | Blue font `0000FF` |
| Key assumption to review | Blue font + yellow fill |
| Formula | Black |
| Link from another sheet | Green `008000` |
| Font | Arial throughout |
| Numbers | `#,##0;(#,##0);"-"`, with negatives in parentheses and zeros shown as `-` |
| Percentages | Stored as fractions (0.15 is displayed as 15.0%) |
| Multiples | `0.00x` |

## 4. Formula rules

- Every assumption sits in its own labelled cell. No hard-coded constants inside formulas, except unit conversions such as 12 months and 365/12 days.
- A row uses the same formula in every period.
- No circular references. Interest is calculated on **opening** balances, and the funding gap is closed with an explicit "equity top-up" line.
- Guard every denominator (`IF(x=0,0,…)` or `IFERROR`).
- Use only functions that work in Excel 2010+ and LibreOffice: `SUMIFS`, `INDEX`, `MATCH`, `CHOOSE`, `IRR`, `EOMONTH`. Do **not** use `XLOOKUP`, `FILTER`, `LET` or dynamic arrays.
- No macros and no external links.

## 5. Checks

Every model includes a `Checks` sheet, where each check returns 0 when OK. The checks are:

- The balance sheet balances in every period.
- Cash flow ties to balance-sheet cash.
- Domain sanity: mix sums to 100%, no negative receivables, limits respected, and so on.

The **master check** appears on the Cover and Dashboard. A model is never released unless it reads `OK` in every scenario.

## 6. Currency

- Each model has one **model currency**, normally local currency (LCY).
- USD items (hardware, hard-currency debt) are converted at the `Timeline` FX path.
- Hard-currency debt is tracked in USD and translated each period. The revaluation goes to P&L as unrealised FX loss or gain.
- Scenario levers always include LCY depreciation.

## 7. Versioning

- Use `vMAJOR.MINOR` in the file name and on the Cover. v0.x means development, v1.0 means the first sellable release.
- Each version has a changelog entry in the volume README.
- The `.xlsx` is generated by `tools/build_*.py`. Never hand-edit a release workbook.

## 8. Defaults and sources

- Default inputs are either **illustrative** (labelled as such in the notes column) or **sourced** (with the source in a cell comment and an entry in `sources/source-register.md`).
- Never present an illustrative value as a benchmark.
