### 1.1 Database schemas [V]

**Data platform (Postgres):**
- `country`, `issuer`
- `security`: ISIN, type, currency, face value, coupon rate, coupon frequency, issue date, maturity, tenor, amortisation, indexation
- `auction`
- `market_observation`
- `bvmac_quote`
- `source`, `source_document`: each document has a URL and a SHA-256 hash
- `auction_extraction`, `extraction_review_event`: the review queue
- `opportunity`: legacy name; the site no longer uses this wording
- `subscription_route`: official subscription procedures; this is not a billing table
- `api_key`, `audit_log`

**Commercial app (Supabase, RLS on every table):**
- `profiles`: email, profile, country, organisation (free text), language, consent, newsletter, watchlist
- `waiting_list`
- `agent_usage`
- Functions `handle_new_abm_user` and `reserve_agent_question`, both SECURITY DEFINER.
- There are no organisation, role, portfolio, subscription or entitlement tables.

### 1.2 External services and data sources [V]
- **Official sources:**
  - UMOA-Titres (auction results, PDF).
  - BEAC (auction notices, PDF, read with OCR).
  - BVMAC (official price list).
  - Lists of primary dealers and intermediaries.
- **Anthropic API:** used by the assistant (Python agent and its TypeScript port). The key is not set yet in Lovable.
- **Netlify:** hosting and the public feed. **Supabase:** authentication and accounts.
- No payment provider. No macroeconomic data source (inflation, debt-to-GDP, fiscal balance).

## 2. Calculation logic is duplicated (main technical debt) [V]

The same bond arithmetic exists **four times**:
1. `backend/app/analytics/calculations.py`: money-market price and yield, coverage ratios, statistics. Uses Decimal.
2. `backend/app/agent/calc.py`: holding, reinvestment, sensitivity, savings goal.
3. `site/simcalc.js`: the static-site simulator.
4. Lovable `src/lib/abm/calculations.ts` and `src/lib/abm/agent/calc.ts`.

Parity is tested between 2 and 3 only. The brief asks for "one analytics calculation engine". The cheapest way to get there:
- one TypeScript engine package, used by the Lovable app and by the static site;
- the Python engine kept for the pipeline;
- a shared set of test vectors (JSON) that both must pass.

## 3. The brief against the data and the licence

| Requirement | Possible now? | Why |
|---|---|---|
| Live indicators on the home page, no hard-coded figures | Yes | The feed already gives counts and the as-of date. The app partly shows them already. |
| Coverage ratios (Module B) | Only for **160 / 2,265** auctions | "Amount offered" is rarely published. The ratio must say "not available" for the rest, never 0 or an estimate. |
| YTM, duration, convexity, accrued interest, clean/dirty price, day counts (ABM Investor) | Yes, **for terms the user enters**. Not reliably for the database securities. | Coupon frequency, issue date, day count and amortisation are missing. Computing them for listed securities would mean guessing terms, which the rules forbid. Prospectuses would have to be collected first. |
| Yield curves | Observed points only: 8 WAEMU countries | Interpolation is possible if labelled. CEMAC publishes prices and discount rates, not yields. A yield derived from them is a CALCULATION and needs the bond's terms. |
| Upcoming auctions | Partly | Only where the official calendar or announcement is ingested (`announcements.py`). |
| Portfolio valuation | Mostly "Market valuation unavailable" | Only BVMAC has trade prices, and they are sparse (81 trading days). |
| Debt-to-GDP, inflation, fiscal balance | No | There is no source yet. One must be chosen and its reuse terms checked. IMF and World Bank are candidates **[U: licence terms not verified here]**. |
| Phase 2–3 countries (Nigeria, Ghana, Kenya, South Africa, North Africa) | No data | Each needs its own source, extractor, checks and reuse authorisation. The schema already accepts any country. |
| Subscriptions, pricing page, paid exports, institutional plans | **Blocked commercially** | `authorisations.json` declares the scope "free_publication_only": no paid product that reproduces the data. The plan and permission architecture can be built and switched off. Charging needs the written authorisations first (letters in `docs/commercial/`). |
| Organisations, team roles, audit log, data isolation | Yes | New Supabase tables with organisation-level RLS. Nothing exists yet. |
| Dark mode, design overhaul, six-product navigation | Yes | Front-end work in Lovable. |

## 4. Risks
1. **Licence (high).** Monetising before the sources answer breaks the declared terms.
2. **Calculation drift (medium).** Four copies of the arithmetic can disagree; today only one pair is tested for parity.
3. **Over-claiming (medium).** Analytics pages for securities whose terms are unknown could show figures that look precise but rest on guessed terms.
4. **Daily routine (medium).** It cannot push or deploy, because the repository is not in its sources and `NETLIFY_AUTH_TOKEN` is missing. Fresh data depends on manual runs.
5. **Assistant cost (low until launch).** Estimated, not measured; it needs the API key.
