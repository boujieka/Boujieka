## 1. Verdict

**Mechanically sound in LibreOffice and in an independent engine; not certified for Microsoft Excel, which was not run.**

* Both workbooks recalculate with 0 error values in 100,857 formulas, master check OK, and reproduce exactly across 426 recalculate and restore cycles, three LibreOffice save cycles and a second formula engine.
* Every required invalid input (132 runs) turns the master check and the Cover status to "ERROR" (text, not an error value) and the decision to STOP.
* All 140 economic direction assertions pass. The static Sensitivity table is reproduced live in both workbooks (worst relative difference 1.2e-12).
* The readiness logic behaves as specified on all four paths. The default reads 2 of 23 and SolaraPay 4 of 23, both STOP on a failed test (gate 10).
* One High finding is a packaging fault, not a formula fault: the release-path copy `output/02_PAYGO_SOLAR_FINANCE_MODEL_v0.8-dev.xlsx` is an older build that reads 3 of 23. Six Medium findings concern decision usefulness (gate 10 is unreachable with debt), input validation, data checks and the timeline of actual credit data.

## 2. Method

* **Engine 1, LibreOffice 24.2.7.2.** Baseline and save cycles were run with `soffice --convert-to xlsx` and the profile supplied, which recalculates on load. The test battery was driven through the LibreOffice UNO API on two private listeners with copies of that profile. For each run the harness set the input cells, ran `calculateAll`, read the outputs, counted error cells with `queryFormulaCells(ERROR)` on every sheet, restored the original cell formulas, recalculated and confirmed that the baseline IRR, master check and gate count came back. All 426 of 426 restores reproduced the baseline.
* **Engine 2, `tools/qa_evaluate.py`** (Python `formulas` 1.3.4). It was run once per workbook on the unmodified files and compared cell by cell with the LibreOffice-converted files. pycel was not used.
* **Static analysis** with openpyxl and the raw OOXML: a function inventory, data validation, charts and a cell-level dependency graph (100,857 nodes, 3,611,288 expanded references, Tarjan strongly connected components).
* **Harness checks.** A planted zero FX rate produced 52,460 error cells and master ERROR, which shows the error counter works. The UNO baseline equals the file-converted baseline.

## 5. Findings

Severity: High = a user can be misled about the model or its status; Medium = a weakness that can let a wrong input or a wrong reading through, or that limits the decision output; Low = presentation or robustness.

### H1 (High). The release-path copy in output/ is a stale build

* **Reproduce:** `output/02_PAYGO_SOLAR_FINANCE_MODEL_v0.8-dev.xlsx` (MD5 d9c35af6..., 09:42) differs from the generator output in volumes/ (095fe913..., 15:45) in 88 cells. Recalculated, Investment_Readiness!B5 reads "3/23 gates met. Decision: STOP (Evidence incomplete: 10 of 13 critical gates not met)". E16 is `=IF(KPIs!$C$64=0,"Met","Not met")`, with no DSCR term and no IFERROR on the automatic gates. The manual (line 32), quick reference, book v0.2 (Ch 16) and case state 2 of 23 and 4 of 23 with STOP on a failed test.
* **Fix:** replace output/02 with the current build and add a hash comparison to checklist item M11.

### M1 (Medium). Gate 10 is unreachable for a debt-financed plan, so the decision is STOP everywhere

* **Reproduce:** default KPIs!E50:I50 = (27.62), (4.98), (1.24), 0.27, 2.25 against Inputs!C73 = 1.20, so KPIs!C65 = 4 and Investment_Readiness!F16 = 0. The definition is DSCR = (CFO + interest) / debt service (KPIs row 50), and CFO absorbs the growth of the receivables book.
* **Scope:** the count of years below the minimum is 3 to 5 in all 30 Sensitivity rows, all 100 mode-grid runs and 64 of 66 stress runs. Only "no debt" (Inputs!C50 = 0, C55 = 0) or Inputs!C73 = (1,000,000,000) gives 0.
* **Effect:** the readiness decision cannot discriminate between cases, and the CONDITIONAL GO and GO paths exist only once the covenant is switched off. The manual presents this as a finding against the plan, which is defensible, but the test definition drives it.
* **Fix:** test coverage on cash available for debt service excluding new originations (a collections-based CFADS), or from the first amortising year. Make the definition an input and show the gate 10 result in the Sensitivity table.

### M2 (Medium). Stale QA statements

* **Reproduce:** 06 section 3 states "3 of 23 ... 5 of 23"; 06 section 5 states that "all critical gates evidenced gave CONDITIONAL GO"; FINAL_QA_REPORT line 32 repeats 3 and 5 of 23.
* **Contrary evidence:** on the current case, with all 16 manual gates and the gate 20 and 22 evidence entered, the decision stays STOP at 21 of 23 until Inputs!C73 is lowered.
* **Fix:** re-issue both documents for the current build.

### M3 (Medium). Data validation does not block invalid entries

* **Reproduce:** all 12 `dataValidation` rules have `showErrorMessage="0"`. Excel therefore accepts 0, 4, 1.5 or text in Inputs!C5, C34, C60 and Credit_Assumptions!C5 without an alert. Inputs!C32, C39, C83 and Consumer_Risk!C5 have no rule at all.
* **Effect:** the checks catch every such entry, but one invalid selector turns 4,782 to 77,069 formula cells into error values (Inputs!C5 = 0 gives 77,069 on the default), so the Dashboard becomes unreadable.
* **Fix:** set `showErrorMessage="1"` with style Stop, add rules to the four switches, and guard the CHOOSE indices.

### M4 (Medium). Fourteen nonsensical inputs pass the master check

The following inputs each pass with master OK, in both workbooks:

* Inputs!C54 = 0: the term loan is never repaid (Financing!BL15 = USD 5,000,000).
* Inputs!C51 = 0 or 61: the loan is never drawn.
* Inputs!C12 = (0.30); Inputs!C57 = 0.
* Products!C25 = 1.5.
* Products!D31 = 1.5: the borrowing base reaches 83% of all gross receivables.
* Products!C26 = 1.2: silently capped at 100%.
* Products!C15 = (25): instalment (760.42), APR shown 0.0%.
* Credit_Assumptions!C20 = 1.5; Credit_Assumptions!C21 = (0.25) with C24 = 0.80.
* Inputs!C81 = C82 = 0.
* Consumer_Risk!C4 = 0 or C8 = 0: readiness flags only.

**Fix:** add range tests to Checks row 26 or a new row, for amortisation and drawdown month (1 to 60), rates, advance rates, hazards, collection rates and shares (0 to 1), and prices (non-negative).

### M5 (Medium). Actual credit history sits on the forecast timeline

* **Reproduce:** Credit_Engine!E38 = `IF(Credit_Assumptions!$C$5=1,E9,INDEX(Credit_Input!$D$8:$D$67,E$4))` places observation n in model month n. In the case, Credit_Input!B8 (28 January 2024) appears on Credit_Portfolio under period end 31 January 2027, beside projected facility headroom.
* **Dates are never read:** Credit_Input!B9 set before B8 changes nothing and passes all checks.
* **Fix:** show history on its own date axis or align by period end, and check that period ends are consecutive month ends.

### M6 (Medium). Seven planted data faults pass (SolaraPay)

The following faults each pass with master OK:

* Vintage_Input!E9 blank and F9 = 200,000 below D9: row 36 compares adjacent checkpoints only.
* Vintage_Input!C9 = (139).
* PERFORM_2026!M43 = 300 with C43 = 150: contracts reaching 2x above contracts.
* PERFORM_2026!F43 = 500 with G43 = 100: PvFin is not tested.
* Credit_Input!D8 = (764,500) with E8 = (871,530).
* Credit_Input!Q9 = 10 x R9.
* Credit_Input!B9 earlier than B8.

**Fix:** compare each checkpoint with the last non-blank earlier one; add non-negativity tests on units and balances; add M <= C and F <= G (or a documented ceiling) to row 41; add a collections-to-due ceiling and a date order test.

### L1 (Low). "Peak equity need" mostly reports the initial equity

* **Reproduce:** KPIs!C57 equals the initial equity (USD 10.0m default, 9.0m case) in 27 of 30 Sensitivity rows and 152 of 196 mode, sensitivity and stress runs. It rises only when top-ups occur (USD 41.9m to 49.6m in Severe-type cases).
* **Fix:** add "additional equity required" and the minimum of FS row 63 (cash before top-up) as headroom.

### L2 (Low). Evidence rules are easy to satisfy

* **Reproduce:** in the case's GO state, a single space in Investment_Readiness!I and J counts as evidence (still 23 of 23), and lower-case "met" counts. Gate 18 stays met with one observation per tier (Credit_Input rows 9 to 67 cleared).
* **Fix:** use `LEN(TRIM())`, and require a minimum history for gate 18.

### L3 (Low). Inventory is stranded when sales stop

* **Reproduce:** Inputs!C18 = 4,000, C19 = 1,000, C20 = C21 = 0. Costs!E22:BL22 then holds LCY 13,544,213 from month 36 to 60 with zero COGS, and the stock enters Year 5 working capital in the valuation.
* **Fix:** add a write-down or obsolescence rule.

### L4 (Low). Engines disagree on SUMIFS with "<>" (case only)

* **Reproduce:** PERFORM_2026!C21:E21 read 0.7795, 0.8153 and 0.8430 in LibreOffice and "no data at M3" in engine 2. C22 reads "no cohort has reached 2x term" in LibreOffice and 0 in engine 2. LibreOffice follows the Excel meaning of "<>" (non-blank).
* **Fix:** replace these criteria with `SUMPRODUCT(ISNUMBER(...)*...)`, and check these cells in the Excel test (the replay CSV covers them).

### L5 (Low). LibreOffice re-encodes charts and constants on save

* **Reproduce:** after a LibreOffice save, series names become literal string references and Sensitivity!B24, C24 and F24 show 0.000001 instead of 1e-06. Nothing else changes.
* **Fix:** distribute generator output only.

## 6. Disagreements with the author's QA (read after testing)

* **Readiness counts:** 06 and FINAL_QA_REPORT give 3 and 5 of 23 with STOP on incomplete evidence. The current files give 2 and 4 of 23 with STOP on a failed test (M2). The brief's expected 2 and 4 of 23 are confirmed.
* **CONDITIONAL GO path:** 06 section 5 says that evidencing all critical gates gave CONDITIONAL GO. At default covenants it now gives STOP (M1).
* **Case cross-engine run:** 06 lists the independent-engine run on the case as not done and argues that the formulas are identical. It was run here, and 4 cells differ because the case uses Vintage_Input paths that the default leaves empty (L4).
* **Fault coverage:** 06 reports that all 12 planted faults were detected. That agrees with the faults it lists, but the wider sweep here found 14 input and 7 data faults that pass (M4, M6).
* **Agreements:** the 2-cell residue of LCY 0.0000011, the Sensitivity reproduction (06: 1.1e-13 and 1.2e-12; here 1.2e-12 worst) and the absence of circular references all agree with the author's results.

## 7. What was not tested

* **Microsoft Excel in any version**, so no claim is made on Excel recalculation, the IRR solver's starting guesses, data validation behaviour, conditional formatting, chart rendering, repair prompts or performance. Readiness gate 17 stays open. The VBA module is untested in Excel.
* **Locale variants** (decimal comma, non-English Excel): `TEXT(B7/C7,"0.0")` on Calibration may render differently.
* **Generator code** (`tools/build_shs_model.py`): only its output was tested.
* **Assumptions:** the realism of inputs, benchmark data and source grading.
* **Other products:** calculators, templates and other workbooks.
* **Inputs not perturbed individually:** combinations beyond the mode grid and the listed stresses; Benchmark and Source_Register sheets beyond the error scan.
